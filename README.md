Откройте START.command из этой версии, выберите «Обновить установленный проект»,
введите GitHub-токен с правами repo и workflow и нажмите кнопку запуска.
Обновление сохраняет канал, секреты, источники, права источников и историю.
Расписание — на 17-й минуте каждого часа (GitHub может задерживать запуск).
После первичного наполнения — максимум один товар за запуск и 24 за день.

Первичное наполнение: до 24 НОВЫХ товаров, прошедших все проверки, за запуск.
Если доступных товаров недостаточно, наполнение продолжается в следующие часы.
Счётчик сохраняется в SQLite и не сбрасывается после повторного обновления.
Наполнение учитывается отдельно от обычного дневного лимита.
Неопределённые отправки повторно не отправляются: они занимают место в лимите
наполнения во избежание дублей. При таких ошибках требуется проверка журнала.
В preview/report.json: backfill.target, backfill.sent, backfill.remaining.

## Названия товаров в версии 7

В заголовке сохраняются извлечённые название, бренд и модель: например, «F13 — умные очки с искусственным интеллектом» и «MILLY POCKET — робот с искусственным интеллектом». ## Формат постов версии 6

Короткое русское название с единственной ракетой, один абзац с 2–3 подтверждёнными функциями, строка «Статус: …» и обязательная концовка «Расчет поставки - @stepan_business». Нет повторного сырого описания, заголовка «Особенности», лишних эмодзи и ссылки «Источник». Исходный URL сохраняется для внутреннего учёта и дедупликации.

Новый editorial.py формирует русские предложения по явным китайским обозначениям функций. Двусмысленное 800W в контексте камеры не переводится как мощность: точное разрешение не публикуется, остаётся подтверждённый факт наличия камеры. Описания комплектов наград и доставки не используются в рекламном абзаце. Для неизвестных формулировок остаётся офлайн-перевод с фильтром смешанного языка и известных ошибочных слов; недостаток надёжных фактов означает пропуск товара. Это снижает количество ошибок, но не гарантирует безупречный перевод произвольного текста.

31 тест проходит, включая регрессию конкретного поста с очками. Изменения применяются к будущим публикациям после обновления проекта; ранее отправленные Telegram-посты автоматически не редактируются. Реальная новая публикация из этой версии ещё не выполнена.

## Обновление уже установленного проекта

Закройте старый установщик, распакуйте новую версию, откройте START.command. Отметьте «Обновить установленный проект», введите только GitHub-токен и имя `china-novelties-telegram`. После обновления автоматически выполняется проверка первого поста, затем включается расписание при успехе.

Версия 5 исправляет подтверждённую причину остановки: для прямых ссылок на изображения используется обычное HTTPS-скачивание без robots.txt. Для каталога и карточек товаров robots.txt по-прежнему проверяется. Это изменение согласовано пользователем после диагностики запрета на фотохостинге Modian. Проверка MIME, размера, формата, публичного HTTPS-адреса и ограничение частоты остаются. Недостаточные или неверно переведённые характеристики по-прежнему приводят к пропуску товара.

Улучшен журнал: показываются причины пропуска фото, а в установщике — название упавшего шага. 27 тестов прошли; реальный повторный запуск исправленной версии пока не выполнен. Текущему подключению помощника GitHub отказал в записи (403), поэтому необходим запуск обновления через локальный установщик.

## Исправление подключения

Версия 4 устанавливает certifi и использует его корневые сертификаты для HTTPS. Проверка сертификата и имени сервера не отключается. Вместо общей ошибки теперь отображаются имя сервиса и код DNS, TLS_CERTIFICATE, TIMEOUT либо NETWORK — без токенов. Само наличие интернета в браузере не подтверждает доступ из Python. При ошибке DNS проверьте системное подключение; исправление сертификатов не исправляет DNS.

1. Распакуйте архив и откройте `START.command` двойным щелчком. Нужен Python 3.11+ и интернет.
2. В локальном окне введите GitHub-токен, токен существующего Telegram-бота и @канал (или -100…). Бот должен быть администратором с правом публикации.

Установщик проверит бота, создаст GitHub-проект, загрузит код, сохранит реквизиты Telegram в зашифрованных Secrets, запустит первую публикацию. Расписание каждый час включится только после успешного реального поста. Оставьте окно установщика открытым до результата. После успешного запуска Mac можно выключить. GitHub-токен после установки можно отозвать. Чужой существующий проект установщик не перезаписывает.

Ссылка для создания GitHub-токена с repo/workflow находится в окне. Токены не записываются в файлы проекта и журнал. Публичный репозиторий раскрывает код и историю публикаций, но не секреты.

## Изменения версии 3

Убраны поля «Товары с разрешёнными фото» и «Основание разрешения на фотографии», а также обязательная проверка ручных записей разрешений перед отправкой. Никакие ссылки на отдельные товары для настройки вводить не нужно. Фото автоматически извлекаются из карточек найденных товаров.

Проверяются доступность, размер и формат фотографий; аватары и служебные картинки исключаются селекторами. При наличии нескольких фото отправляется альбом из 2–5 изображений с общей подписью. Один снимок допускается, когда извлечена только одна уникальная ссылка и файл успешно проверен. Если найдено несколько изображений, но удалось получить лишь одно, товар пропускается. Полнота галереи зависит от разметки источника.

Автоматическое извлечение не устанавливает лицензию и не является подтверждением прав на перепубликацию. Убрана именно обязательная ручная проверка в программе; никаких вымышленных разрешений код не создаёт.

## Реализовано

- Modian: каталог, название, срок и дата краудфандинга, число поддержавших, галерея, явные характеристики. Селекторы сверены с живой страницей в браузере.
- Универсальный JSON-LD Product адаптер. Xiaomi, Made-in-China и дополнительные площадки сейчас отключены или ещё не подключены.
- Argos Translate zh→en→ru / en→ru; модели скачиваются и кэшируются, перевод работает локально без LLM/API.
- Не более 6 товаров в сутки по Москве, 1 за запуск. Если подходящих товаров мало, публикаций будет меньше. Неизвестные характеристики и цены не сочиняются.
- SQLite: дедупликация URL, названия, бренд+модель и точных нормализованных изображений. Не гарантирует распознавание OEM-дублей с разными названиями и фото.
- Ветка `parser-state`: состояние сохраняется ДО отправки в Telegram. При потерянном ответе запись остаётся pending/uncertain и не повторяется автоматически.
- Проверка robots.txt, задержки запросов, ошибки источников и причины пропуска в диагностическом JSON. Обхода блокировок нет.

## Ручной запуск и диагностика

```bash
python3.11 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python scripts/install_models.py
python -m unittest discover -s tests -v
python scripts/probe.py
python parser.py
```

В config.json включаются источники и фиксируется проверка их условий (`terms_reviewed`). Установщик делает это по отметке пользователя. `rights.json` теперь необязателен для ручного описания конкретных товаров: пустой объект допустим; поля `image_urls` могут переопределить галерею, `verified_facts` с `facts_evidence` — дополнить подтверждённые характеристики. Его историческое имя сохранено для совместимости. Наличие `allowed`/`evidence` больше не требуется для публикации.

Для реальной отправки установите переменные окружения TELEGRAM_BOT_TOKEN и TELEGRAM_CHAT_ID, затем запустите `python parser.py --send`. Не запускайте локальную публикацию одновременно с облачной: у них отдельные базы.

В Actions доступны probe, preview, send, activate. Последний требует хотя бы одного успешного поста. Отчёт — артефакт collector-diagnostics, ошибки — SQLite errors. Расписание: 17-я минута каждого четвёртого часа UTC, возможны задержки GitHub. Для остановки задайте переменную репозитория PUBLISH_ENABLED=false.

Pending/uncertain сначала проверьте по каналу. Не удаляйте всю историю: если отсутствие конкретного поста подтверждено, удалите только соответствующие media и deliveries, чтобы разрешить повтор.

Приватные репозитории расходуют квоты аккаунта. Кэш моделей и артефакты также зависят от правил GitHub.
