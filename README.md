# China Novelties — исправление публикаций
## Установка обновления в существующий канал
1. Распакуйте эту версию в новую папку. Закройте старый установщик.
2. Откройте START.command.
3. Выберите «Обновить установленный проект», укажите GitHub-токен с repo/workflow.
4. Нажмите запуск. Telegram Secrets и история останутся прежними.
Не передавайте токены в чат.

## Изменения
- Почасовой cron на 17-й минуте каждого часа.
- Убрана зависимость расписания от PUBLISH_ENABLED и открытого окна Mac.
- Установщик явно включает workflow до ручного запуска проверки.
- До 5 страниц Modian и 60 карточек; сбой следующей страницы не теряет уже найденные.
- Текст из раздела проекта, а не только заголовка. Награды/доставка не служат характеристиками.
- Китайские рекламные слоганы не публикуются через свободный машинный перевод.
- Проверенные русские шаблоны; модель сохраняется в заголовке, контакт — в конце.
- Достаточно одного подтверждённого содержательного факта без заполнения выдуманными.
- Невыполненная попытка отправки теперь делает запуск ошибочным, сохраняя отчёт.
- GitHub Summary показывает количество постов и причины пропуска.
- 38 тестов пройдены, включая включение расписания при обрыве локального установщика.

## Ограничения, которые остаются
Публикуются только подтверждённые товары с доступными фотографиями.
Расписание не гарантирует наличие нового подходящего товара каждый час.
Первичное наполнение — цель 24 новых товара, не доказательство наличия 24 кандидатов.
Товары старше 45 дней не используются для искусственного наполнения.
Xiaomi и Made-in-China не включены: надёжные адаптеры и определение даты новизны ещё нужны.
Архив сам по себе не меняет работающий GitHub: требуется запуск установщика.
Работу расписания подтверждает запуск с событием schedule в GitHub Actions,
а публикацию — sent > 0 в preview/report.json и сообщения Telegram.
Новая отправка из этой рабочей сессии не выполнялась: нет доступа записи GitHub/Telegram.

## Работа и диагностика
В Actions: режим preview проверяет без отправки, send публикует, probe проверяет источники.
При необходимости остановки отключите workflow в GitHub Actions.
История и защита от дублей — в ветке parser-state.
После неопределённого результата Telegram товар не отправляется повторно автоматически.
Неполное наполнение видно в report.json: backfill.target, sent, remaining.
Постоянная работа не использует ChatGPT и платные LLM API.
